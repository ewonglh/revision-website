| Docling local layout/OCR [S11]          | Local processing, reading order, tables, code/formula enrichment, original asset retention; avoids sending the entire course pack to a provider           | Python/models/native dependencies and processing compute belong outside the lightweight API runtime; equations/wires/nesting still need review. Measure cold setup and repair time, not just token cost                            |

Structured JSON alone establishes no fidelity                    |

No route has measured equation error, structure fidelity or minutes/page here. Direct document input does not replace a canonical extracted representation with source anchors. Keep raw original, derived blocks/assets, review patches and a new immutable published revision; do not replace the original with Markdown. Human acceptance of a diagram is distinct from functional-equivalence checking. Unsupported or low-confidence pages can remain readable while excluded from automatic marking.

Measured on the received pack ([details](README.md#local-extraction-evidence-from-the-received-pack)), the deterministic `get_text()` route mangles this material in four ways: TeX big operators decode to ASCII letters, symbol glyphs land in the Private Use Area, subscripts flatten, and diagram topology is absent. On the CS2100 pages the same extractor turns merged-header datapath tables into `None`-headed cells and splits `[$1]–[$3]` across cells.

But the route is not one thing, and a same-day measurement says so. `find_tables()` recovers the ruled grids those pages draw: the `5×A` table on `tut07_selected_ans` p5 scored 10/10 data rows against arithmetic, and the `p3` adder table 16/16. Reading those same rendered pages as images at the DeepSeek 1024-token downscale scored **5/10** on the `5×A` table, with errors concentrated in the low-order nibble. On the large-type comparator page, by contrast, the image reading passed 5/5 executed truth-table checks.

So the comparison in #27 is not "which extractor loses least" and not "vision for everything". **The owner has confirmed the mixed route, 12 November 2026:** deterministic extractors and a vision pass are used together, selected per content type rather than one being chosen for the library. Ruled tables go to `find_tables()`, labelled diagrams and prose to vision, wires to geometry plus a netlist reconstructor, TeX math to symbol canonicalisation or vision. Where both can read the same block, their disagreement is itself a check.

The strongest single finding is that a fluent vision reading of a dense table can be half wrong, so vision output needs a non-vision check wherever one exists. The cost argument for mixing is weak — a vision page is capped at 1,024 tokens, about $0.00015–$0.00031 — so mixing earns its place by giving a cross-check, not by saving money.

A page-image route on the owner's chosen provider is now documented: `deepseek-flash` accepts images [S23], so the same model that would mark answers can also read a rendered page. Note the specific limits, and note that the in-session measurement above was taken at exactly the resolution those limits imply:

- **PDF is not accepted.** Pages must be rendered to PNG/JPEG first, which is a local step and already measured here (2.7 s and 7.0 MB for 55 pages at 200 dpi).
- **1024 tokens per image maximum.** Pages are downscaled to roughly a 1300x1300 pixel budget. A dense A4 page lands near 1093x1545 and remained legible in a spot check of the CS2100 circuit pages and answer keys; dense multipart notation at small point size was not exhausted.
- **No accuracy claim.** Legibility to a human eye is not recognition accuracy, and the one dense-table measurement here was 5/10. Vision output still needs the same repair record and source anchor, and an unreviewed transcription remains unmarkable.

The correlation worth avoiding: using the same model for OCR, retrieval summary and marking means a misread symbol propagates through every stage without an independent check. A separate extraction route, or human confirmation of diagram interpretation, keeps the error detectable.

Sources: Cloudflare billing/limits/delivery [S01–S08], Supabase plans/RLS [S09–S10], processing [S11, S18]. Neither an inexpensive platform floor nor managed authentication proves the product's access rules. A long-running request or client polling loop must not own durable work. Do not use eventually consistent caches as authoritative deadlines or answer state.

Proposal: shortlist A and B, with C available for native parsing/checkers, and retain manual reviewed import for the first tiny real pack. Pick only after #26–#29 and the review in #30. Prefer one durable orchestrator for a slice; do not install Workflows, Queues and a second task framework for identical responsibilities. If Workflows performs steps directly, Queue billing is an alternative dispatcher calculation, not a required duplicate service. A portable job record/checkpoint and transactional outbox remains necessary wherever jobs cross the DB boundary.

## Marking and retrieval routes

Owner follow-up: DeepSeek through a custom API provider is the preferred route within a $20/month AI budget and approximately 1,000 responses/day. It must be evaluated first against typed answers and the agreed provisional/manual-review policy. The owner specifies DeepSeek-V4.1-Flash-1017 at official API rates, microdollar billing (USD), and 1,000 submitted answers/day. Official alias/rates/cache rules are documented in S19–S22; custom-provider passthrough, limits and retention terms remain untested; the OpenAI/Claude routes below remain priced comparators, not the implementation default. Do not treat direct-provider prices or a model label as proof of custom-provider cost or fidelity. The [cost worksheet](costs.md) now leads with the owner's constraint.

No tools capable of reading other sources or executing learner code should be available to the model by default. A retrieved definition supports a criterion; it does not certify the student's inference.
