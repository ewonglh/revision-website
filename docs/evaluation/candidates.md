## Extracting one intact reviewed problem

| Route                                   | Documented capabilities / fit                                                                                                                             | Fidelity risks and repair work to measure                                                                                                                                                                                          |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Manual entry plus original crops        | Portable baseline for a small first question set; owner controls prompt, parts, key and anchors                                                           | Human time, transcription errors, anchors and repeated editing; time the entire review, not just copying text                                                                                                                      |
| Docling local layout/OCR [S11]          | Local processing, reading order, tables, code/formula enrichment, original asset retention; avoids sending the entire course pack to a provider           | Python/models/native dependencies and processing compute belong outside the lightweight API runtime; equations/wires/nesting still need review. Measure cold setup and repair time, not just token cost                            |
| Mistral document OCR [S12–S13]          | Page Markdown, images/bounding boxes, table formatting and optional structural blocks; pinned `mistral-ocr-2512` is a documented available price baseline | OCR output is not a reviewed question/rubric graph; reconstruct parts, marks, assets and anchors. OCR 4 is documented as newer; evaluate an accessible current pinned route in #27 and reprice rather than silently using `latest` |
| OpenAI direct file/page input [S14–S15] | File guide documents PDF text plus page images for compatible vision models; can propose structured question/diagram interpretations                      | Rendering/transcription may change symbols and wires; token/image expense and model changes; outputs need the same human repair and original-page reconciliation. Structured JSON alone establishes no fidelity                    |

No route has measured equation error, structure fidelity or minutes/page here. Direct document input does not replace a canonical extracted representation with source anchors. Keep raw original, derived blocks/assets, review patches and a new immutable published revision; do not replace the original with Markdown. Human acceptance of a diagram is distinct from functional-equivalence checking. Unsupported or low-confidence pages can remain readable while excluded from automatic marking.

Measured on the received pack ([details](README.md#local-extraction-evidence-from-the-received-pack)), raw text-layer extraction is not a safe marking input for either module:

- TeX-generated pages extract with every glyph present but 50 big-operator glyphs decoded as the ASCII letters `P`/`X`, plus flattened subscripts. The text reads fluently and is wrong, so no automated confidence signal fires.
- Circuit pages hold the topology only as vector paths. Truth tables extract; the gates and wires they accompany do not.
- Pages whose diagram or table is a raster image yield only the slide title.
- Handwritten annotations carry no text, so any worked solution written on the slides is invisible to a text pipeline.

That splits the requirement rather than selecting a product: equation-bearing pages need symbol canonicalisation and both halves of script recovery, while diagram-bearing pages need a rendered crop and a human-confirmed interpretation. Neither is supplied by whichever extraction route is cheapest per page, so repair effort — not page price — is the figure that decides this in #27.

A page-image route on the owner's chosen provider is now documented: `deepseek-flash` accepts images [S23], so the same model that would mark answers can also read a rendered page. This is the cheapest way to cover the gap above, but note the specific limits before relying on it:

- **PDF is not accepted.** Pages must be rendered to PNG/JPEG first, which is a local step and already measured here (2.7 s and 7.0 MB for 55 pages at 200 dpi).
- **1024 tokens per image maximum.** Pages are downscaled to roughly a 1300x1300 pixel budget. A dense A4 page lands near 1093x1545 and remained legible in a spot check of the CS2100 circuit pages and answer keys; dense multipart notation at small point size was not exhausted.
- **No accuracy claim.** Legibility to a human eye is not recognition accuracy. Vision output still needs the same repair record and source anchor, and an unreviewed transcription remains unmarkable.

The correlation worth avoiding: using the same model for OCR, retrieval summary and marking means a misread symbol propagates through every stage without an independent check. A separate extraction route, or human confirmation of diagram interpretation, keeps the error detectable.

| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| C: thin API plus separate container/local processing | Either A or B for identity/storage; worker receives only scoped immutable job references                          | Docling/OCR pre-processing or a sandboxed ISA checker on separately managed compute, e.g. Cloud Run jobs [S18]; durable external scheduler and callbacks                                                                        | Native dependencies, memory and sandbox controls fit more naturally here; introduces IAM, signed callbacks, cold start, image maintenance, region/egress and job-minimum billing. This is a processing placement option, not a replacement for auth/DB/storage                                    |

Sources: Cloudflare billing/limits/delivery [S01–S08], Supabase plans/RLS [S09–S10], processing [S11, S18]. Neither an inexpensive platform floor nor managed authentication proves the product's access rules. A long-running request or client polling loop must not own durable work. Do not use eventually consistent caches as authoritative deadlines or answer state.

Proposal: shortlist A and B, with C available for native parsing/checkers, and retain manual reviewed import for the first tiny real pack. Pick only after #26–#29 and the review in #30. Prefer one durable orchestrator for a slice; do not install Workflows, Queues and a second task framework for identical responsibilities. If Workflows performs steps directly, Queue billing is an alternative dispatcher calculation, not a required duplicate service. A portable job record/checkpoint and transactional outbox remains necessary wherever jobs cross the DB boundary.

## Marking and retrieval routes

Owner follow-up: DeepSeek through a custom API provider is the preferred route within a $20/month AI budget and approximately 1,000 responses/day. It must be evaluated first against typed answers and the agreed provisional/manual-review policy. The owner specifies DeepSeek-V4.1-Flash-1017 at official API rates, microdollar billing (USD), and 1,000 submitted answers/day. Official alias/rates/cache rules are documented in S19–S22; custom-provider passthrough, limits and retention terms remain untested; the OpenAI/Claude routes below remain priced comparators, not the implementation default. Do not treat direct-provider prices or a model label as proof of custom-provider cost or fidelity. The [cost worksheet](costs.md) now leads with the owner's constraint.

The price worksheet uses specified token counts for transparency, not provider-independent token equivalence. Check billed reasoning/image tokens and schema overhead during measurement. No tools capable of reading other sources or executing learner code should be available to the model by default. Providers receive only the minimum authorised evidence, with the retention/deletion terms reviewed first [S16]. A retrieved definition supports a criterion; it does not certify the student's inference.
